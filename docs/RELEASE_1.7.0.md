# Besanj 1.7.0 - هوش قیمت شخصی

## هدف

این نسخه به بسنج یک لایه تحلیل قیمت اضافه می کند که فقط از سابقه ثبت شده خود کاربر استفاده می کند. هدف این نیست که قیمت بازار اینترنت را حدس بزنیم یا توصیه مالی قطعی بدهیم؛ هدف این است که کاربر بتواند بفهمد قیمت فعلی نسبت به سابقه خودش در همان پرونده کجا ایستاده و فروشنده ها در پرونده های قابل مقایسه معمولاً چه جایگاه قیمتی داشته اند.

## تحلیل داخل پرونده

- بهترین قیمت فعلی از آخرین قیمت هر فروشنده محاسبه می شود.
- برای ساخت سابقه زمانی، در هر روز فقط کمترین قیمت همان روز به عنوان snapshot روزانه نگه داشته می شود تا چند استعلام در یک روز وزن مصنوعی ایجاد نکنند.
- کف، میانه و سقف سابقه از snapshotهای روزانه به دست می آیند.
- سیگنال قیمت فقط وقتی فعال می شود که حداقل سه روز سابقه ثبت شده باشد.
- سیگنال های قابل نمایش: «داده کم»، «نیاز به استعلام تازه»، «در کف سابقه»، «مناسب»، «معمولی» و «بالاتر از سابقه».
- قیمت stale یا expired حتی اگر در کف سابقه باشد فرصت خرید محسوب نمی شود و به استعلام تازه هدایت می شود.
- روند اخیر با مقایسه پنجره های اخیر snapshot روزانه محاسبه می شود و به صورت کاهشی، تقریباً ثابت یا افزایشی نمایش داده می شود.
- سطح اطمینان از تعداد روزهای سابقه و تعداد فروشنده های دارای قیمت ساخته می شود.

## Insights

- بخش «هوش قیمت شخصی» مستقل از خرید نهایی است و با داده استعلام هم کار می کند.
- تعداد پرونده های قابل ارزیابی، تعداد قیمت های مناسب یا بهتر، تعداد پرونده های بالاتر از سابقه و میانگین فاصله فعلی از میانه سابقه نمایش داده می شود.
- اگر پرونده فعال با قیمت مناسب و سابقه کافی وجود داشته باشد، بهترین فرصت فعلی به صورت لینک مستقیم به پرونده نشان داده می شود.
- فیلتر دسته و برچسب موجود Insights روی همین تحلیل هم اعمال می شود.

## حافظه قیمتی فروشنده

برای مقایسه فروشنده ها قیمت خام کالاهای متفاوت با هم جمع نمی شود. در هر پرونده:

1. آخرین قیمت هر فروشنده گرفته می شود.
2. کمترین قیمت همان پرونده مبنا قرار می گیرد.
3. فاصله قیمت فروشنده از آن کف به درصد تبدیل می شود.
4. میانه این فاصله در چند پرونده، جایگاه قیمتی فروشنده را می سازد.

نتیجه در پروفایل فروشنده و Insights نمایش داده می شود. این بخش تعداد پرونده قابل مقایسه، فاصله معمول از ارزان ترین قیمت و دفعات ارزان ترین بودن را نشان می دهد.

## حریم خصوصی و معماری

- هیچ API قیمت، crawler، سرویس AI یا endpoint بیرونی برای این قابلیت استفاده نمی شود.
- تحلیل در مرورگر و روی داده های موجود IndexedDB انجام می شود.
- مسیر اختیاری Groq فقط برای Speech-to-Text باقی مانده و هیچ ارتباطی با Price Intelligence ندارد.
- Dexie همچنان v7 است و migration جدیدی اضافه نشده است.
- Backup format ساختاری تغییر نکرده و فقط `appVersion` به 1.7.0 رسیده است.
- dependency جدید npm اضافه نشده است.
- Service Worker cache version: `besanj-shell-v20`.

## گیت کیفیت

Guard جدید:

```text
check:price-intelligence
```

این Guard بررسی می کند که:

- تحلیل سابقه پرونده و جایگاه فروشنده وجود داشته باشد.
- stale/expired به عنوان فرصت خرید نشان داده نشود.
- UI پرونده، Insights و Seller به تحلیل وصل باشند.
- قابلیت Price Intelligence هیچ `fetch`، API قیمت یا credential ابری نداشته باشد.
- تست های regression مربوط به قیمت پایین، قیمت قدیمی، فروشنده گران و فرصت شخصی وجود داشته باشند.

گیت کامل مقصد:

```bash
npm install
npm audit
npm run check
```

## Smoke test پیشنهادی

1. یک پرونده با دو فروشنده بساز و در سه روز مختلف قیمت ثبت کن.
2. قیمت روز سوم را پایین تر از روزهای قبلی ثبت کن؛ کارت «هوش قیمت شخصی» باید «در کف سابقه» یا «مناسب» نشان دهد.
3. همان پرونده را با قیمت های قدیمی تست کن؛ سیگنال باید به «نیاز به استعلام تازه» تغییر کند.
4. وارد Insights شو؛ همان پرونده باید در بخش هوش قیمت شخصی قابل ارزیابی باشد.
5. برای یک فروشنده در دست کم دو پرونده قیمت ثبت کن و در هر پرونده یک رقیب هم داشته باش؛ صفحه Seller باید جایگاه قیمتی را نشان دهد.
6. فیلتر دسته و برچسب Insights را تغییر بده و مطمئن شو اعداد هوش قیمت هم با همان فیلتر تغییر می کنند.
7. Voice، Templates، Backup، Seller، PWA و Tooltipها را یک بار smoke test کن تا regression دیده نشود.
