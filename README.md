# بسنج — Besanj

بسنج یک دفتر شخصی و local-first برای استعلام قیمت، پیگیری فروشنده‌ها، مقایسه گزینه‌ها و رسیدن به تصمیم خرید است.

نسخه: **0.7.0**

## فاز 0.7 — ارتباط، گزارش و خط زمانی

این فاز بسنج را از یک فضای ثبت و تصمیم به ابزاری برای اقدام و ارائه نتیجه نزدیک‌تر می‌کند.

- اکشن سریع فروشنده روی کارت استعلام: تماس، پیامک، واتساپ و کپی متن آماده پیگیری.
- متن پیگیری با نام پرونده، نام فروشنده، آخرین قیمت و تاریخ اعتبار ساخته می‌شود.
- تب «رویدادها» برای دیدن خط زمانی پرونده: ساخت پرونده، اضافه‌شدن فروشنده، استعلام، پیگیری، فایل و انتخاب نهایی فعلی.
- صفحه گزارش مستقل برای هر پرونده در مسیر `/cases/[id]/report`.
- گزارش شامل بودجه، شروط خرید، آخرین قیمت فروشنده‌ها، انتخاب نهایی و پیگیری‌های باز است.
- دکمه «چاپ / ذخیره PDF» با stylesheet مخصوص A4؛ بدون وابستگی PDF اضافه.
- Web Share API برای اشتراک خلاصه گزارش و fallback به Clipboard.
- گزارش متنی قابل کپی برای فرستادن در پیام‌رسان یا ایمیل.
- انتخاب نهایی تاریخی هم در گزارش حفظ می‌شود، حتی اگر همان فروشنده بعداً قیمت تازه‌تری ثبت کرده باشد.
- Guard جدید `check:report` برای محافظت از سیم‌کشی گزارش، خط زمانی، تماس سریع و چاپ.

## فاز 0.6 — مالکیت داده و خرید تکراری

این فاز روی دو نیاز مهم بعد از اضافه‌شدن پیگیری و پیوست تمرکز دارد: حفظ مطمئن داده و شروع سریع خریدهای تکراری.

- دانلود **پشتیبان کامل** از پرونده‌ها، فروشنده‌ها، استعلام‌ها، پیگیری‌ها، پیوست‌های باینری و تنظیمات ظاهر.
- فرمت پشتیبان نسخه‌دار با شناسه `besanj-backup` و بررسی ساختار فایل قبل از Restore.
- بازیابی دو مرحله‌ای؛ فایل ابتدا بررسی و خلاصه‌اش نمایش داده می‌شود و تا تأیید نهایی هیچ داده‌ای تغییر نمی‌کند.
- Restore کامل و transactional داخل Dexie؛ داده فعلی فقط بعد از تأیید با محتوای پشتیبان جایگزین می‌شود.
- کنترل سلامت پیوست‌ها هنگام Restore با بررسی حجم واقعی داده باینری.
- «خرید مشابه» برای ساخت پرونده تازه از روی یک پرونده قبلی.
- امکان کپی انتخابی بودجه هدف، شرط‌های خرید و فروشنده‌ها.
- قیمت‌ها، انتخاب نهایی، پیگیری‌ها و پیوست‌ها عمداً در خرید مشابه کپی نمی‌شوند تا تاریخچه خرید جدید مستقل بماند.
- انتخاب سریع فروشنده قبلی هنگام ثبت استعلام؛ نام و شماره به فرم منتقل می‌شود.
- Guard جدید `check:data` برای جلوگیری از حذف اتفاقی قابلیت‌های Backup/Restore و Repeat Purchase.

## فاز 0.5 — از ثبت قیمت تا پیگیری خرید

- بودجه هدف برای هر پرونده و نمایش وضعیت هر پیشنهاد نسبت به بودجه.
- شروط و معیارهای خرید و ثبت میزان پوشش آن‌ها روی هر استعلام.
- امتیاز اعتماد فروشنده از ۱ تا ۵ همراه با یادداشت تجربه.
- یادآوری پیگیری برای پرونده یا فروشنده.
- بخش «کارهای امروز» در داشبورد.
- پیوست عکس، PDF و فایل به استعلام‌ها.
- تصمیم‌یار با توجه به بودجه، پوشش شروط و امتیاز فروشنده.

## قابلیت‌های پایه

- پرونده جدا برای هر خرید یا خدمت.
- ثبت چند استعلام با فروشنده، قیمت، هزینه جانبی، تاریخ، اعتبار قیمت، تحویل، گارانتی، پرداخت، کانال تماس و یادداشت.
- تاریخچه کامل هر فروشنده و استعلام مجدد بدون overwrite قیمت قبلی.
- انتخاب تا ۴ گزینه برای مقایسه کنار هم.
- تب مقایسه، نمودار قیمت، تاریخچه، تصمیم‌یار و جزئیات.
- فیلترهای فروشنده، کانال، تازگی، قیمت، تحویل، گارانتی و بازه تاریخ.
- انتخاب و لغو شفاف گزینه نهایی.
- Dashboard با جست‌وجو، فیلتر نوع/پیگیری و چند حالت مرتب‌سازی.
- Light / Dark / System با آبی برند به‌عنوان رنگ پیش‌فرض، چند پالت جایگزین و رنگ سفارشی.
- تغییر سریع Light/Dark و پالت از Navbar.
- PWA قابل نصب با Web Manifest، Service Worker و آیکن maskable.
- local-first با Dexie؛ بدون Login و Backend.

## رابط فارسی

- `lang="fa"` و `dir="rtl"` از root.
- فونت Mikhak و ارقام نمایشی فارسی.
- PriceInput و IntegerInput فارسی.
- Selectهای PersianLabs با `items` map.
- DatePicker جلالی با موتور Doran و هماهنگی با Light/Dark/Custom Theme.
- Popover در دسکتاپ و Bottom Sheet قابل drag-to-dismiss در موبایل.

## داده و Migration

نام دیتابیس عمداً تغییر نکرده است تا داده کاربران نسخه‌های قبلی از بین نرود:

```text
estelamkoo-local
```

Schema version همچنان **4** است و برای فازهای 0.6 و 0.7 جدول جدیدی لازم نیست.

```text
purchaseCases
providers
quotes
reminders
attachments
```

فاز 0.6 جریان Backup/Restore و Duplicate را روی همین داده‌ها اضافه کرد و فاز 0.7 گزارش/Timeline را از همین داده‌ها می‌سازد؛ بنابراین migration دیتابیس جدیدی ندارد.

## پشتیبان کامل

Settings > «پشتیبان و انتقال داده»

فایل خروجی JSON شامل این موارد است:

```text
purchaseCases
providers
quotes
reminders
attachments (base64)
theme / palette preferences
```

نام فایل نمونه:

```text
besanj-backup-20260908.json
```

Restore به‌صورت **جایگزینی کامل** انجام می‌شود، نه Merge. قبل از Restore بهتر است از داده فعلی یک خروجی بگیری. حداکثر اندازه فایل ورودی در UI فعلی ۱۲۸ مگابایت است.

### نکته درباره local-first

پیوست‌ها و داده‌ها هنوز روی همان Browser/Profile ذخیره می‌شوند. Backup فاز 0.6 راه انتقال و بازیابی دستی را فراهم می‌کند؛ Cloud Sync و حساب کاربری هنوز وجود ندارند.

## خرید مشابه

در تب «جزئیات» هر پرونده دکمه «خرید مشابه» وجود دارد. کاربر می‌تواند انتخاب کند:

- بودجه هدف کپی شود یا نه.
- شرط‌های خرید کپی شوند یا نه.
- فروشنده‌ها همراه شماره و امتیاز اعتماد کپی شوند یا نه.

استعلام‌ها و قیمت‌های قبلی کپی نمی‌شوند.

وقتی فروشنده‌های قبلی داخل پرونده وجود داشته باشند، فرم «ثبت استعلام» یک Select برای انتخاب سریع آن‌ها نشان می‌دهد.

## محدودیت فایل‌های پیوست

- حداکثر ۵ فایل برای هر استعلام.
- حداکثر ۸ مگابایت برای هر فایل.
- حداکثر ۲۴ مگابایت مجموع فایل‌های یک استعلام.
- تصویر، PDF، Word، Excel و فایل متنی در فرم انتخاب می‌شوند.

## نصب و اجرا

نسخه پیشنهادی Node در `.nvmrc` ثبت شده است.

```bash
npm install
npm run dev
```

## کنترل کیفیت

گیت کامل:

```bash
npm run check
```

ترتیب اجرا:

```text
doctor
check:ui
check:theme
check:pwa
check:workflow
check:data
check:report
typecheck
lint
test
build
```

`check:data` بررسی می‌کند که Backup/Restore، نگهداری بایت‌های پیوست، خرید مشابه و انتخاب فروشنده قبلی واقعاً در سورس سیم‌کشی شده باشند. `check:report` نیز صفحه گزارش، چاپ/PDF، اشتراک، خط زمانی و تماس سریع را بررسی می‌کند.

## نصب به‌عنوان اپ (PWA)

Service Worker فقط در production ثبت می‌شود تا `next dev` درگیر cache قدیمی نشود.

```bash
npm run build
npm start
```

Service Worker cache version در این نسخه:

```text
besanj-shell-v8
```
